Проектная работа "Веб-ларек"

«Веб-ларёк» — это веб-приложение интернет-магазина, реализующее функционал просмотра каталога товаров, добавления их в корзину и оформления заказа.

Стек: HTML, SCSS, TS, Vite

Структура проекта

    src/ — исходные файлы проекта.

    src/components/ — директория компонентов бизнес-логики и интерфейса.

    src/components/base/ — директория базовых классов приложения.

Ключевые файлы

    src/pages/index.html — корневой HTML-шаблон страницы.

    src/types/index.ts — декларация глобальных типов и интерфейсов.

    src/index.ts — точка входа приложения.

    src/styles/styles.scss — корневой файл таблиц стилей.

    src/utils/constants.ts — конфигурация глобальных констант.

    src/utils/utils.ts — набор вспомогательных утилит.

Установка и запуск
    Для установки зависимостей и запуска локального dev-сервера выполните в терминале команду npm install, а затем npm run start. При использовании пакетного менеджера Yarn выполните команду yarn, а затем yarn start.

Сборка проекта
    Для сборки проекта в production-режим выполните команду npm run build (или yarn build).

Архитектура приложения
    Проект спроектирован в соответствии с парадигмой MVP (Model-View-Presenter). Архитектура разделена на три основных слоя:

    Model (Модель) — управляет данными, их хранением и бизнес-логикой.

    View (Отображение) — отвечает за рендеринг интерфейса и обработку пользовательского ввода.

    Presenter (Представитель) — выступает посредником между Моделью и Отображением, реагируя на события.

    Взаимодействие между компонентами реализовано на базе событийно-ориентированного подхода (Event Emitter).

Типы данных (src/types/index.ts)
Основные интерфейсы и типы, описывающие структуру данных приложения:

    Интерфейс IProduct (Товар): содержит идентификатор (id), описание (description), ссылку на изображение (image), название (title), категорию (category) и цену (price).

    Тип TPayment: описывает доступные способы оплаты (card или cash).

    Интерфейс IBuyer (Данные покупателя): содержит выбранный способ оплаты (payment), электронную почту (email), телефон (phone) и адрес доставки (address).

    Интерфейс IOrder (Структура заказа): расширяет данные покупателя, добавляя общую сумму заказа (total) и массив идентификаторов купленных товаров (items).

    Интерфейс IOrderResult (Ответ сервера): содержит идентификатор оформленного заказа (id) и итоговую сумму (total).

Базовые классы

    Класс Api
    Обеспечивает базовую логику отправки HTTP-запросов к серверу. Конструктор принимает базовый URL API и глобальные настройки запросов.

    Метод get — выполняет GET-запрос по указанному эндпоинту. Возвращает Promise с ответом сервера.

    Метод post — выполняет запрос (по умолчанию POST) по указанному эндпоинту, передавая данные в теле запроса в формате JSON. Возвращает Promise с ответом сервера.

    Класс EventEmitter
    Брокер событий, реализующий паттерн «Наблюдатель». Обеспечивает обмен сообщениями между компонентами приложения. Конструктор инициализирует структуру данных для хранения подписчиков.

    Метод on — устанавливает обработчик на определенное событие.

    Метод emit — инициирует событие, передавая подписчикам данные.

    Метод trigger — возвращает функцию, вызов которой инициирует событие с заданным контекстом.

    Классы слоя «Модели» (Управление данными)

    Класс Products
    Хранит коллекцию товаров (каталог) и состояние товара, выбранного для детального просмотра.

    Метод setItems — записывает массив товаров в каталог.

    Метод getItems — возвращает текущий массив товаров каталога.

    Метод getProduct — ищет и возвращает объект товара по его идентификатору.

    Метод setPreview — устанавливает переданный товар в качестве активного для предпросмотра.

    Метод getPreview — возвращает товар, находящийся в состоянии предпросмотра.

    Класс Cart
    Управляет состоянием корзины пользователя.

    Метод getItems — возвращает список товаров, добавленных в корзину.

    Метод addProduct — добавляет товар в корзину.

    Метод removeProduct — удаляет товар из корзины по его идентификатору.

    Метод clearCart — полностью очищает корзину.

    Метод getTotalPrice — вычисляет и возвращает суммарную стоимость всех товаров в корзине.

    Метод getTotalCount — возвращает общее количество товаров в корзине.

    Метод containsProduct — проверяет, присутствует ли конкретный товар в корзине.

    Класс Buyer
    Отвечает за хранение, управление и валидацию контактной информации пользователя и данных о доставке.

    Метод setField — записывает переданное значение в указанное свойство данных покупателя.

    Метод getBuyerInfo — возвращает объект, содержащий все текущие данные покупателя.

    Метод clearBuyer — сбрасывает все свойства класса к пустым значениям.

    Метод validate — проверяет наличие данных об адресе и способе оплаты, а также наличие контактных данных (email, телефон). Возвращает объект с описанием ошибок для незаполненных полей.

Слой коммуникации (API)

    Класс LarekAPI
    Предоставляет методы для предметного взаимодействия с backend-частью приложения. Использует базовый класс Api.

    Метод getProductList — запрашивает список товаров с сервера. Возвращает Promise с массивом объектов товаров.

    Метод orderProducts — отправляет сформированный заказ на сервер. Возвращает Promise с результатом оформления заказа.


Архитектура приложения

    Код приложения разделен на слои согласно парадигме MVP (Model-View-Presenter):
    Model (Слой данных): отвечает за хранение и изменение данных.
    View (Слой представления): отвечает за отображение данных на странице и реакцию на действия пользователя.
    Presenter (Слой связи): связывает данные и отображение, обрабатывая события при помощи брокера событий.

    В роли Presenter выступает код в основном файле src/main.ts (или index.ts), который инициализирует все классы и настраивает обработчики событий.

Базовый код

Класс Api
    Содержит в себе базовую логику отправки запросов.
    Методы:
    get — выполняет GET-запрос на переданный в параметрах эндпоинт и возвращает промис с объектом, которым ответил сервер.
    post — принимает объект с данными, которые будут переданы в JSON в теле запроса, и отправляет эти данные на эндпоинт, переданный как параметр при вызове метода. По умолчанию выполняется POST-запрос, но метод запроса может быть переопределен заданием третьего параметра при вызове.  

Класс EventEmitter
    Брокер событий, реализующий паттерн Наблюдатель. Позволяет подписываться на события и инициировать их, обеспечивая связь между слоями приложения без прямой зависимости классов друг от друга.
    Основные методы:
    on — подписка на событие.
    emit — инициализация события.
    trigger — возвращает функцию, при вызове которой генерируется заданное событие.  

Класс Component
    Базовый абстрактный класс для всех компонентов слоя представления. Обеспечивает инструментарий для работы с DOM.
    Методы:
    setImage — устанавливает изображение и альтернативный текст.
    render — принимает данные, объединяет их с компонентом и возвращает корневой DOM-элемент.

Слой данных (Model)

Класс Products
    Управляет каталогом товаров.
    Хранит массив товаров (items) и товар, выбранный для просмотра в модальном окне (preview).
    Методы: setItems (обновляет каталог и вызывает событие), getProduct, setPreview.

Класс Cart
    Управляет корзиной покупок.
    Методы: addProduct, removeProduct, clearCart, getTotalPrice, getTotalCount, containsProduct. При изменениях генерирует соответствующие события.

Класс Buyer
    Управляет данными пользователя при оформлении заказа.
    Хранит поля: способ оплаты, email, телефон, адрес.
    Методы: setField (устанавливает значение конкретного поля), validate (проверяет заполненность полей и возвращает объект с ошибками), clearBuyer.

Класс LarekAPI
    Расширяет базовый класс Api, содержит методы конкретно для работы с бэкендом Веб-ларька (получение списка товаров с добавлением пути до CDN и отправка заказа).

Слой представления (View)

Класс Page
    Управляет отображением главной страницы.
    Наследуется от Component.
    Отвечает за вывод каталога товаров, обновление счетчика корзины и блокировку прокрутки страницы при открытии модального окна.

Класс Modal
    Управляет модальным окном.
    Методы open и close. Поддерживает закрытие по клику на оверлей и крестик.

Базовый класс Card и его наследники
    Отвечает за отображение карточки товара.
    Card — базовый класс, управляет заголовком и ценой.
    CatalogItem (наследник Card) — используется для вывода товаров на главной странице. Управляет изображением и бейджем категории (с динамическим изменением цвета).
    PreviewItem (наследник CatalogItem) — используется для отображения подробной информации в модальном окне. Управляет кнопкой добавления и описанием. Блокирует кнопку, если товар бесценный.
    BasketItem (наследник Card) — используется для вывода товаров в корзине (добавляет порядковый номер).

Класс Basket
    Отображает список добавленных товаров, итоговую сумму и кнопку оформления заказа. При отсутствии товаров выводит надпись Корзина пуста и блокирует кнопку.

Класс Form и его наследники
    Управляет базовыми формами, прослушивает события ввода (input) и отправки (submit), выводит ошибки валидации.
    OrderForm — форма выбора способа оплаты и адреса. Реализует переключение активности кнопок оплаты.
    ContactsForm — форма ввода почты и телефона.

Класс Success
    Отображает окно успешного оформления заказа с итоговой суммой списанных синапсов.

Взаимодействие компонентов (События)

В приложении используются следующие события:
items:changed — изменение массива товаров в каталоге.
card:select — выбор карточки товара для открытия превью.
preview:changed — изменение товара в модальном окне превью.
basket:add / basket:remove — добавление/удаление товара из корзины.
basket:changed — изменение состава корзины.
basket:open / order:open — открытие модальных окон корзины и первого шага оформления заказа.
order.payment:change — изменение способа оплаты.
order.:change / contacts.:change — изменение полей в формах.
formErrors:change — изменение состояния валидации форм.
order:submit — успешный переход от формы адреса к форме контактов.
contacts:submit — итоговая отправка заказа на сервер.
